# Changelog

## Unreleased

- Mirrored skill files keep their executable bit. A canonical `.agents/skills/<name>/helper.sh` with `+x` now lands in `.claude/skills/<name>/` with `+x`; `check` reports a mode mismatch as `mode:<path>`, and `sync` repairs it even when only the mode differs. Mode handling is skipped on Windows.
- Generated files now say `Generated by rolesync sync; edit canonical .agents sources.` instead of naming `scripts/sync_agents.py`, which consumer projects do not have. The first `rolesync check` after upgrading reports every generated role file as drifted; `rolesync sync` rewrites them in place because their content still matches the recorded manifest, so no "Refusing to overwrite" error occurs. Commit the regenerated files afterwards.
- Clearer errors when adopting an existing project: the symlink and untracked-file refusals now say what to do, and the README gains an "Adopting an existing project" section covering the Claude main-session `agent` setting and the git pathspec commit pitfall.
- Catalog schema additions. All are optional, and existing catalogs render byte-for-byte the same:
  - `codex.sandbox_mode`, `claude.tools`, `claude.permissionMode`, and `claude.maxTurns` may be omitted or `null`. No line is rendered, so the runtime inherits the parent's setting instead of a pinned default.
  - `skill` may be omitted or `null`, `skills` accepts a list (merged after `skill`), and `claude.preloadSkills: false` keeps skills out of the Claude `skills:` frontmatter while leaving the body reference. A role with no skill gets no `skills:` line and no "Primary workflow" line; several skills render one "Workflow skills" line.
  - Native Claude frontmatter passes through from the `claude` object: `disallowedTools`, `color`, `mcpServers`, `hooks`, `memory`, `background`, `initialPrompt`, and `omitClaudeMd`.
  - `platforms` on a role limits it to `["claude"]` or `["codex"]`; outputs for the other platform are pruned as stale.
  - `.agents/roles/<stem>.claude.md` and `<stem>.codex.md` appendices are appended after the shared body for that platform only.

## 1.0.1 - 2026-09-24

- Finish the RoleSync rebrand in the `minimal` preset: generated roles are now `rolesync-orchestrator`, `rolesync-coder`, and `rolesync-reviewer` (skills `rolesync-orchestrate`, `rolesync-implement`, `rolesync-review`) instead of the leftover `loom-*` names shipped in 1.0.0.
- New projects store their platform selection in `.agents/rolesync.json`. Existing `.agents/loom.json` files are still read as a legacy fallback, including by `doctor`.
- Projects already initialized with `loom-*` names keep them, because `.agents/catalog.json` is user-owned. To switch, rename the entries in `.agents/catalog.json` and the matching `.agents/skills/loom-*` directories, then run `rolesync sync`; stale generated `loom-*` files are removed automatically.

## 1.0.0 - 2026-09-22

- Promote to a stable 1.0.0 release; no functional changes from 1.0.0rc1 beyond the items below.
- Fix `--version`'s fallback (used when the package metadata isn't available, e.g. running from a source checkout) to read from the package's single `__version__` instead of a separately hardcoded string.
- Correct README install/release notes now that the package is published and Trusted Publishing is confirmed working end-to-end.

## 1.0.0rc1 - 2026-09-22

- Renamed the project from `agent-loom` to RoleSync (PyPI package `rolesync`, CLI command `rolesync`) because the `agent-loom` name was already taken on PyPI.
- Package RoleSync as an installable Python CLI with `init`, `sync`, `check`, and `doctor` commands.
- Add `minimal` and `github-workflow` project presets and per-project Claude/Codex platform selection.
- Harden generated-file ownership against path traversal, symlink escapes, and malformed manifests.
- Mirror binary skill resources byte-for-byte while rejecting common secret-file patterns and transient files.
- Add cross-process locking plus recoverable staged synchronization for interrupted writes.
- Add cross-platform CI, built-wheel smoke testing, and a PyPI Trusted Publishing workflow.
